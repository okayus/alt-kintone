# フェーズ13: やりとりのサイドパネル化 — 閉じられて、幅を変えられる

> 設計判断は 2026-08-11〜12 の会話で確定済み（推奨6件を全採用）。この文書はその**固定**。
> 会話にしか無い決定を実装より先に書き落とすこと自体が、このフェーズの段取り（§8）の一部。

## 0. 要求

> チャット風UIをページの一番したではなく、サイドから見れるようにでき、邪魔なときは閉じるようにしたい。
> チャットの表示幅もクリックしながら調整できるようにしたい。

適用は**案件詳細・要望詳細の両方**（決定済み）。サーバは触らない — フェーズ12 と同じく
`packages/*` の差分ゼロで完了する見込み（完了条件10）。

動機の言い換え: いまのやりとりはページ最下部の区画で、(a) 本文（案件の内容・活動・変更案）を
**見ながら**書けない、(b) 高さが 320px 固定で履歴が読みにくい、(c) 要らないときも場所を取る。
サイドパネルは (a)〜(c) を同時に解く。

## 1. 現状（2026-08-11 実測）

- `ChatPanel`（`shell/chat/`）は fetch を知らない表示部品で、**自前のスクロール容器**を持つ
  （`.chat-log` が `max-height: 320px` で内側スクロール）。最下部追随（`stick`）・
  「新着 n 件 ↓」・IME ガードは全部この容器の中 → **置き場を変えても追随ロジックは持ち運べる**
- 取得は `DealChat` / `RequestChat` の `useQuery` + `refetchInterval: 8000`。
  **unmount するとポーリングは止まる**（閉じる＝unmount にすると新着に気づけない）
- レイアウトは「ページ全体が文書としてスクロール」する構え（ヘッダ・ナビも固定ではない）。
  詳細画面の `app-main` は `max-width: 1100px`。サイドパネルに相当する構造は無い
- localStorage の前例は `shell/auth/dev-user.ts`（切替ユーザーの保存）
- `RequestChat` は `onPosted` で出口条件 `replied`（起票者に返信した）の読み直しに繋がっている
- 要望の既読（`markRead`）は**要望詳細を開いた時点**で走る（パネルの表示とは無関係）

## 2. 決定（2026-08-11〜12 の会話で確定）

- **決定A（レイアウト）: push + viewport 貼り付け**。本文を狭める（overlay で隠さない —
  チャットは本文を見ながら書くもの）。詳細画面は `max-width: 1100px` なので、広い画面では
  パネルは**余白を食うだけで本文が動かない**。パネルとトグルは sticky/fixed で viewport に
  貼り付く（ページ最下部から動かした意味は「スクロール位置によらず見える」ことにある）。
  狭い画面は幅クランプの下限で守るだけで、overlay への切替モードは作らない（PC中心）
- **決定B（状態の置き場）**: **既定は「開」**。開閉は localStorage に**画面種別ごと**
  （案件と要望で別 — 補助と本体で閉じたい度合いが違う）、**幅は共通で1つ**（幅の好みは
  画面ではなくモニタのもの）。URL には載せない（共有リンクに閲覧の好みを混ぜない）。
  ⚠ クランプは**ドラッグ中だけでなく適用時にも**効かせる — 広いモニタで保存した幅を
  狭いウィンドウで適用すると本文が消える
- **決定C（閉じている間の新着）**: 輸送は**ポーリングのまま**（8秒。`refetchInterval`）。
  閉じても unmount せず**非表示のままクエリを生かし**、トグルに「**閉じてから増えた件数**」を出す。
  サーバに未読状態を持たない — これは `ChatPanel` の「新着 n 件 ↓」の**同型**（視界から
  外した間の増分合図）であって、未読機構ではない。**「未読は作らない」（フェーズ11 論点I）は
  維持**: 既読・未読線・ナビのバッジは引き続き作らない。
  ⚠ キーに `user` が入るので利用者切替で件数の基準ごと別クエリになる。
  **`placeholderData` を付けない**（決定N系 — 前の人の件数を一瞬も出さない）。
  ⚠ `display: none` 中は scrollHeight が計れないので、**開いた瞬間に最下部へ**を明示的に扱う
- **決定D（既読のタイミング）**: `markRead` は**今のまま**（要望詳細を開いたら既読）。
  パネルを閉じたまま開くと「バッジは消えたのに読んでいない」が起こり得るが、既定開なので
  ズレるのは自分で閉じた人だけ。返事の本体（変更案・対応内容）は本文側にも出る。
  実害が観測されたらパネル表示に紐づけ直す
- **決定E（活動との非対称）**: サイド常駐で「一番手軽な入力欄」が常にチャットになり、
  顧客接触の報告が活動でなくチャットに流れるリスクが上がる（フェーズ11 論点F の再燃）。
  v1 と同じく**見出しと説明文の言葉だけで持たせ、それ以上の手当はスコープ外**。
  ズレは観測可能（チャットに接触報告が書かれる／活動が減る）なので、起きてから考える
- **決定F（操作の範囲）**: リサイズは**ポインタ操作のみ**（`setPointerCapture`。依存なし）
  + **ダブルクリックで既定幅**。`role="separator"` + 矢印キーは見送り（要る合図が出たら）。
  **Esc で閉じる**。開いても**フォーカスは移さない**（読みに開く人の邪魔をしない。
  書く人はクリック1回）
- **決定G（機構の置き場）**: パネル（開閉・幅・ハンドル・トグル）は `shell/panel/`。
  **children を受けるだけでチャットを知らない**「形が固定の機構」（実装ハブ 決定13）。
  汎用化の判断は先送りできる形にしておく
- **決定H（マウント位置）**: パネルは**詳細画面の中**。App（シェル）に持ち上げない —
  やりとりはレコード1件に紐づき、一覧・参照画面には指す対象が無いので、画面をまたいで
  持ち回るものが無い。詳細画面内なら案件を移ると remount され、スクロール・追随・件数の
  リセットが今と同じ理屈で済む
- **決定I（閉じている間のエラー）**: 閉じている間の取得失敗は**黙らせる**（`meta.silent` 相当を
  開閉で切り替え）。見えていない機構のエラーで上部バナーを赤くしない。実害は「件数が
  止まる」だけで、開けば従来どおりバナーに出る
- **決定J（部品の不変条件）**: `ChatPanel` は fetch を知らないまま。`RequestChat` の
  `onPosted`（`replied` の自動充足）も配線そのまま。**既存の ChatPanel browser テスト4群が
  無変更で通ること**を設計の匂い検知に使う（完了条件10）

## 3. 見送った「知る手段」（調査 2026-08-11。再訪のための記録）

push を入れる日が来たときの設計指針だけ固定する:
**チャンネルはデータを運ばず「変わった」という合図だけ運び、データは今の REST で取り直す**
（認可の判定を REST 1本に保つ。TanStack Query とは `invalidateQueries` で繋がり、
`keyOf` の規約から「`asOf` 付き＝過去表示は無効化しない」が述語で書ける）。

| 手段 | 評価 | 見送り理由 / 再訪条件 |
|---|---|---|
| **SSE** | **push するならこれ一択** | 片方向で足り（書き込みは REST に残す）、`node:http` も Go も標準ライブラリのみ。⚠ `EventSource` はカスタムヘッダ不可 → `X-Dev-User` はクエリか fetch-SSE、将来は cookie で自然解消。**再訪条件: AI 参加者の高頻度投稿、または既読・プレゼンスの要件化** |
| 変更フィード型ポーリング | 中間解として優秀 | SCD2 のおかげで「いつ以降に何が変わったか」が**ほぼタダ**（全テーブルに validFrom）。ポーリング1本に束ねられ、**API を通らない書き込み（seed / diff --request）も拾える** |
| WebSocket | 過剰 | 双方向が余る（書き込みを WS に載せると認可の一本道が崩れるので載せない）。Node・Go とも依存が要る。再訪は既読・入力中・プレゼンスが要件化したとき |
| GraphQL subscriptions | 不適 | 旧論点16 の決着（REST 自動生成・GraphQL 見送り）と衝突し、下は同じ WS/SSE なので利得が無い |
| WebTransport | クラス違い | HTTP/3 のメディア・ゲーム級低遅延用。2026-03 に Baseline 化したがサーバ側実装・経路の対応が別途要る |
| Web Push / メール | **別の問題** | 上記は全部「開いている人」にしか届かない。要件が「開いていない人への到達」なら、このクラス（比較先はメール通知） |

インフラのメモ: Cloud Run はストリームがリクエストタイムアウト（最大60分）で切れる →
再接続前提の設計になる。合図＋REST 取り直しの形なら切断は `refetchOnReconnect` が治す。

## 4. タスク（依存順）

1. **`shell/panel/`**: クランプ・件数基準の**純関数**（unit テスト対象）、幅と開閉の
   localStorage フック、`SidePanel` 部品（開閉・リサイズハンドル・トグルボタン・Esc）
2. **案件詳細に組み込み** + CSS（push レイアウト・viewport 貼り付け・上部バナーを覆わない。
   `.chat-log` の `max-height: 320px` はパネル内では「残り全部」に変わる）
3. **要望詳細に組み込み**（本文の再構成: 対象・対応者/対応内容・変更案が本文、やりとりがパネル。
   変更案を見ながら返事を書けるようになる）
4. **閉じている間**: 非表示マウントでクエリ維持・「閉じてから増えた件数」・`silent` の開閉切替・
   開いた瞬間の最下部スクロール
5. **テスト**: unit（クランプ・件数の基準）+ browser（ドラッグで幅が変わる/クランプ/永続化・
   開閉とスクロールの復元・Esc・利用者切替で件数が即消える）。既存4群の生存確認

## 5. 完了条件（/phase-done で検証）

[P] = Playwright MCP（`localhost:5273`）で踏む / [B] = browser テスト / [V] = verify

1. [P] 案件詳細を開くと、やりとりが**右のパネルに開いた状態**で出る。ページ最下部に
   チャット区画は無い（最後の区画は活動）
2. [P] ハンドルをドラッグすると幅が変わり、**リロードしても保たれる**。ダブルクリックで既定幅
3. [P] 閉じると本文が広がり、リロードしても閉じたまま。**案件で閉じても要望詳細では開いている**
   （画面種別ごと）。Esc でも閉じる
4. [P] 閉じている間に別ユーザーとして投稿（curl で POST）→ **8秒程度でトグルに件数が出る**。
   開くと件数が消え、最新のメッセージが見えている
5. [P] 過去の時点（`as_of`）では入力欄が畳まれ、理由が言葉で出る（従来挙動の維持）
6. [P] 要望詳細でも同じパネルで動き、やりとりを書くと「起票者に返信した」が充足に変わる
   （`onPosted` の配線維持）
7. [B] 保存された幅がウィンドウに対して大きすぎるとき、**適用時にクランプ**され本文の最小幅が保たれる
8. [B] 最下部に居るとき新着に追随し、上を読んでいる最中は「新着 n 件 ↓」— 既存挙動がパネル内でも
   変わらない（既存テストの生存で担保）
9. [B] **閉じている間**の取得失敗は上部バナーに出ず、**開いている間**の失敗は出る
10. [V] `pnpm verify` green。**既存 ChatPanel browser テスト4群が無変更で通る**。
    `packages/*` の差分ゼロ
11. [B] 利用者を切り替えた瞬間、前の利用者の件数がトグルに一瞬も出ない（決定N系）

## 6. スコープに入れないもの

- SSE / WebSocket 等の push（§3 に固定。実装ハブ「作らないもの」の SSE 行から参照）
- 未読の機構（既読・未読線・ナビバッジ）— フェーズ11 論点I の判断を維持
- 活動の起票の軽量化（決定E で言葉のみと決めた側の手当）
- キーボードでのリサイズ（`role="separator"` + 矢印キー）
- モバイル・狭幅の専用対応（クランプ下限のみ）
- リサイズ中の追随維持（ResizeObserver）— 下記「受け入れる挙動差」

## 7. 壊れうるもの・受け入れる挙動差

- **リサイズ中の再レンダ**: まず素直に幅を state 直結で書く。カクつくなら CSS 変数 + ref 直書き
  + pointerup で確定に切り替える（フェーズ6 の教訓 — 計画でなく実測で決める）
- **リサイズで折り返しが変わり、最下部貼り付きからズレる**: v1 は許容（追随は件数変化でしか
  発火しない）。ResizeObserver は足さない
- **push の帰結として、パネルが開いていると本文が狭い**: 仕様（閉じられるのが対の手当）
- **（要望）閉じたまま開くと未読バッジが消える**: 決定D で許容済み

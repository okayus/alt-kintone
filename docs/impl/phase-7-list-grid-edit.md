## 0. 要求

フェーズ6の仮想スクロール一覧に、セル編集を足す（論点E・F の推奨を初期値とする）:

- セルのフォーカスモデル（クリック・矢印キー・Tab / Shift+Tab で移動。状態は `{行, 列}` 1つ）
- **Enter で編集開始 → セル位置に実 `<input>` / `<select>` をマウント → Enter 確定 / Esc 取消**
- 確定 = `PATCH` 1回 = 有効期間型の1バージョン（行単位の保存ボタンは持たない）
- 型別セルエディタ（候補とラベルは定義から取る）

- 確定成功 → レスポンスの行で置換 + 世代を進める（論点B）
- 競合は v1 では現状の 409 のみ（論点F。precondition 方式は必要になってから）

## 2. 前提の解説

論点の手前に、判断に使う概念を並べる（フェーズ6 §2 と同じ流儀）。

### 2-1. 論理フォーカスと DOM フォーカスは別物

仮想化はフォーカスの前提を壊す。セルの DOM 要素はスクロールで消えるので、
**roving tabindex**（各セルに tabindex を配り、DOM フォーカス自体を行き来させる
グリッドの標準手法）は使えない — フォーカス中のセルがアンマウントされた瞬間に
DOM フォーカスが body に落ち、キーボードが死ぬ。

そこで2つを分ける:

- **DOM フォーカス**はスクロール枠（`tabIndex=0` の `.grid-scroller`）が持ち続け、
  keydown はそこで受ける
- **論理フォーカス**（どのセルにいるか）は React 状態 `{row, col}` 1つ。描画されている行に
  だけハイライトが乗る。画面外に出ても状態は残り、矢印を押せば `scrollToIndex` で戻れる

DOM フォーカスが実 `<input>` に移るのは**編集中だけ**。確定・取消でスクロール枠に返す。
編集中に行が画面外へ出るとエディタごとアンマウントされるが、draft は React 状態が持つので
スクロールで戻れば編集中のまま復元される（フォーカスが body に落ちた場合の血路はクリック）。

### 2-2. IME の変換確定と Enter

変換確定の Enter は「**文字列を**確定する」操作で、「**セルを**確定する」操作ではない。
区別しないと、日本語の案件名は変換を確定するたびに PATCH が飛んで一文字も直せない
（完了条件3が独立の条件になっているのはこのため）。

ブラウザは合成中のキーに印を付ける: `KeyboardEvent.isComposing`（合成セッション中は
true）と、レガシーな `keyCode === 229`。Chrome / Firefox は変換確定の Enter keydown が
`isComposing: true` で届くので、これを無視すれば足りる。
⚠ Safari は `compositionend` が先に飛び、確定 Enter が `isComposing: false` で届く既知の
癖がある。`keyCode === 229` の併用でおおむね塞がるが、検証は Chrome で行い
Safari は完了条件に含めない（PC 中心・社内利用の決定に従う）。

対象は text エディタだけ（number / month / select に IME は絡まない）。

### 2-3. 「編集したら世代を進める」とスクロール位置の衝突

3つの既決定をそのまま組むと破綻する:

1. 論点B: 編集成功で**世代を進める**（snapshot を取り直す）。固定時点のまま新しい行を
   重ねると、1画面に2つの時点が混ざるため
2. 決定J: 世代が変わったら**スクロールを先頭に戻す**
3. 現実装: 世代の開始は**ハードリセット**（行を捨て、total を undefined にし、
   全面「読み込み中…」を出す）

→ Enter で確定するたびに一覧が白くなって先頭へ飛ぶ。「下のセルへ移って次を直す」という
スプレッドシートの基本動作が成立しない。

解きほぐすと、決定Jの動機は「**絞り込みが変わって、いまの位置の意味が消えた**」場合の
話であって、編集では位置の意味は保たれている。つまり「世代を進める」には2種類ある:
**条件が変わった**（ハード: 行を捨て、先頭へ）と、**時点だけ取り直す**（ソフト: 行と
スクロールを保持したまま snapshot と total を更新する）。→ 決定K

### 2-4. 金額系の自動判定が読むのは請求額で、いまの列に無い

完了条件2の例「金額を入れると自動判定が充足に変わる」の自動判定
（`budget_confirmed` / `amount_presented`）は、`initialBilling` / `monthlyBilling`
（**請求額**）を読む（`amountEntered`、`packages/definitions/src/flows/sales.ts`）。

ところがグリッドの金額列は**自社収益の合成列**（`initialProfit` + `monthlyProfit`）だけで、
これは論点F が「計算列＝編集不可」とした側。つまり**いまの列構成のままでは完了条件2が
成立しない**。導入時期（`expectedCloseMonth` → `timing_confirmed`）でも自動判定は変わるが、
ヨミ管理で営業が一覧上で直すものの筆頭はまさに金額なので、例を弱めるのではなく列を足す。
→ 決定L

## 3. 着手時に決めたこと（決定K〜Q）

### 決定K: 編集の確定は「ソフト世代」— スクロールと行表示を保ったまま時点を取り直す

`useDealPage` を次の形にする:

- `resetKey`（スクロールを先頭に戻す合図）は **key（絞り込み・並び・`as_of`・ユーザー）
  だけ**から作る。世代番号を含めない。決定Jは「条件が変わった世代」に限定される
- `replaceRow(index, record)` を足す。確定成功時に PATCH レスポンスで**その場で置換**する
  （未確認件数のセルが即座に変わるのはこれ。裏の再取得を待たない）
- `refresh()`（旧 `reload` の作り替え。未使用は確認済み）: token を進めて古い応答と
  requested を捨てるが、**rows と total は保持**する（スケルトンにしない）。最後に見えて
  いた範囲の先頭ページを snapshot 無しで引き直し、返ってきた `now` を新しい snapshot に
  据える。見えている残りは既存の `ensureRange` 経路が埋める
- 編集した行がソート順の中で動く・絞り込みから外れて total が減るのは**仕様**
  （論点F・B のまま）。位置基準の論理フォーカスは動かさない（フォーカス下の行が
  入れ替わることを許容する）

1枚目だけ snapshot 無し・残りは固定という構造上の隙間はフェーズ6の世代開始と同じで、
同じ理由で許容する。

### 決定L: 請求額2列（一時金・月額）をグリッドに足す

`initialBilling` / `monthlyBilling` の列を自社収益列の左に追加する（右寄せ・ソート可・
integer エディタ）。**自社収益（合成）列は表示のまま残す** — 予測・目標は粗利ベースという
決定（sales-domain.md）の帰結で、一覧の主役の数字は粗利のほう。編集できるのは素の
フィールドで、見るのは合成、という分担になる。integer エディタの実対象がこれで生まれる
（現状の列には integer の編集対象が1つも無い）。

列が2つ増えるので `min-width`（CSS の 1080px、`.grid-head` / `.grid-row` / `.grid-canvas`
の3箇所）を実際のテンプレート幅に合わせて上げる。横スクロールは既にある。

### 決定M: 詳細への導線は先頭のリンク列に移し、案件名は編集セルにする

案件名セルはいま詳細への `<a>` を兼ねている。セル編集を入れると、**クリックが
「フォーカスする」と「navigate する」で衝突**し、マウスでは案件名を編集できなくなる。
先頭に幅 44px 程度のリンク列（「開く」）を足し、案件名はプレーンな text 編集セルにする。
kintone の一覧がレコード詳細への導線をアイコン列にしているのと同じ解法。

### 決定N: キー操作のモデル（§4 に仕様表）

- Enter = 確定して**下へ**、Tab / Shift+Tab = 確定して**右 / 左へ**、Esc = 取消
  （論点E の「確定後は下のセルへ」を含む、スプレッドシートの既定に合わせる）
- **値が変わっていない確定は PATCH を送らない**（同値の版を積まない。`DealForm` の
  「変更なし」と同じ線）。移動だけする
- ダブルクリックでも編集開始（Enter と等価。マウスだけで完結させる）
- 他所へのクリック（blur）= 確定。取消は Esc だけ（黙って捨てない）
- IME 変換確定の Enter は無視（§2-2。`isComposing || keyCode === 229`）
- フォーカスモードの Esc はセルフォーカス解除（解除すると Tab がグリッドの外へ抜ける。
  Tab をセル移動に使う間はキーボードがグリッドに閉じるので、出口を1つ残す）
- 編集中の矢印キーはエディタのもの（テキストのカーソル移動・select の候補移動）。
  セル移動しない

### 決定O: 編集可否の3種と見た目

| 種類 | どのセルか | 見た目 |
|---|---|---|
| 行が書けない | `_permissions.update` が false（担当外・`as_of` 中） | **行全体に薄い地色**（フォーカス前から分かる = 完了条件4）。フォーカス枠はグレー |
| 列が編集対象外 | リンク列 / FK（顧客企業・担当）/ 合成（自社収益）/ フロー列（現在ステップ） | 通常表示。フォーカス枠だけグレー（Enter は無反応） |
| 編集可 | §4 の8列 × 書ける行 | フォーカス枠がアクセント色。編集中は実エディタ + 保存中マーク |

行レベルを文字色でなく地色にするのは、担当フィルタを外した一覧では**他人の行が多数派**で、
文字を薄くすると一覧そのものが読みにくくなるため。

### 決定P: 失敗の扱い — 事前に弾けるものはセルで、サーバ失敗はバナーで

- **FE の事前検証**: 必須（title / productType / dealType / status）の空、integer の
  非整数は、セルを invalid 表示にして**送らない**（Enter で確定できない。Esc は常に効く）。
  `DealForm` が送る前に止めているのと同じ範囲
- **サーバ失敗**（403 / 409 / 500…）: エディタは確定時に閉じている（応答 12ms 前後に
  UI を同期させない）ので、既存のバナー（`onError`、hint 表示）で知らせ、行は置換しない
  （旧値のまま）。**409 は追加で `refresh()`** — 「最新を読み直してから更新する」という
  サーバの hint を UI がそのまま実行する形。draft が失われるのは許容する
  （同時書き手は rowFilter でほぼ居ない、という論点F の前提と同じ根拠）

### 決定Q: select は change では確定しない

閉じた `<select>` の ↑↓ は押すたび change が発火する。change 確定にすると候補を
眺めるだけで版が積まれるので、確定は他の型と同じ **Enter / Tab / blur** に揃える。
マウス操作（開いて選ぶ→他所クリック）は blur 確定で自然に閉じる。
⚠ プラットフォームによっては Enter が select を開く/選ぶ動作を持つ。T6 の実機で
挙動を確認し、必要なら keydown の透過条件を調整する。

### 決定R: 枠が見えている ＝ キーが効く、を不変条件にする（初回検証後に欠陥として発見）

論理フォーカスと DOM フォーカスの分離（§2-1）には代償があった。**グリッドの外を
1回クリックすると、DOM フォーカスは body へ落ちるのに論理フォーカス（枠）は
描かれたまま残り、「枠は出ているのに Enter がどこにも届かない」という嘘の状態になる**。
実機で「フォーカスしてあるセルで Enter を押しても何も起こらない」として発覚した。
§7 の当初検証は毎回「セルをクリック → 直後に Enter」だったのでこの経路を踏んで
いない（検証が通った ＝ この経路が無い、ではなかった）。

修正は2つ:

- **DOM フォーカスがグリッドの外へ出たら論理フォーカスも消す**（スクロール枠の
  focusout。`relatedTarget` がグリッド内なら消さない — エディタへの移動はグリッド内で
  完結し、keydown はスクロール枠までバブルするので枠は嘘にならない）。編集中
  （invalid のまま外をクリックした場合）は draft と赤枠を守るため消さない
- **フォーカスが無い状態の矢印 / Enter は、見えている先頭行に枠を置く**（Tab で
  グリッドに入ったあと、キーボードだけで編集まで辿り着ける。Tab 自体は奪わない —
  素通りできないとキーボードでグリッドから出られなくなる）

これで枠の意味が「キーがこのセルに効く」と常に一致する。残る「Enter で何も
起きない」はすべて意図した不可で、枠の色で区別が付く（グレー枠 = 編集対象外の列・
書けない行、青枠 = 編集可）。

### 決定S: 編集に入れないときは、理由をその場に言葉で出す（2件目の報告を受けて）

決定Rの後も「編集モードが効かない」という報告が続いた。実体は**設計どおりの編集不可**
（開発用ユーザーが佐藤のまま、更新順で先頭に並んだ山田の案件を編集しようとしていた。
§7 追記3）だが、**設計どおりの拒否が2回続けて不具合として報告された**なら、
グレー枠と行の地色という決定Oの表現だけでは足りていない。

Enter / ダブルクリックで編集に入れなかったとき、理由を一覧の上に表示する
（`.grid-blocked`。次に編集が始まるかハード世代が変わるまで残す）:

- 行が書けない: 「この案件の担当は 山田 太郎。編集できるのは担当者本人と管理者だけ
  （いま 佐藤 花子 として操作している）」— 担当者名と**いま誰として操作しているか**まで
  出す。名前は masters から引く
- `as_of` 中: 「過去の時点を見ているので読み取り専用」
- 編集対象外の列（リンク・FK・合成・フロー列）: 「「◯◯」列は一覧では編集できない」

認可の判定はサーバの `_permissions` のまま（§4-1。FE で再判定しない）。ここで足したのは
**判定結果の説明**だけで、判定を持つ場所は増えていない。

## 4. キー操作と編集のふるまい（仕様）

**フォーカスモード**（DOM フォーカスはスクロール枠、論理フォーカス `{row, col}`）:

| 入力 | 動作 |
|---|---|
| クリック | そのセルへフォーカス |
| ↑ ↓ ← → | 移動（端でクランプ）。`scrollToIndex` で追従 |
| Tab / Shift+Tab | 右 / 左へ。行末で次行頭へ折り返し（preventDefault） |
| Enter / ダブルクリック | 編集開始（編集可のセルのみ。不可セルでは無反応） |
| Esc | セルフォーカス解除（Tab がグリッドの外へ抜けられる状態に戻す） |

**編集モード**（セル位置に実エディタ、DOM フォーカスはエディタ）:

| 入力 | 動作 |
|---|---|
| Enter | 確定 → 下のセルへ（IME 変換確定の Enter は無視） |
| Tab / Shift+Tab | 確定 → 右 / 左のセルへ |
| Esc | 取消（draft を捨てる）→ フォーカスモード |
| 他所クリック（blur） | 確定 |

**エディタと編集可能列**（候補・ラベルは定義から。`DealForm` と同じ線）:

| 型 | エディタ | 空の扱い | 対象列 |
|---|---|---|---|
| text | `<input type="text">` | null（title は必須なので invalid） | title |
| integer | `<input type="number" step="1">` | null。非整数は invalid | **initialBilling・monthlyBilling（決定Lで追加）** |
| enum（必須） | `<select>`（`{key, label}`） | 空の選択肢を出さない | productType・dealType・status |
| enum（任意） | `<select>`（先頭に「—」） | null | confidence |
| yearMonth | `<input type="month">` | null | expectedCloseMonth |

編集対象外の列: リンク列（決定M）/ 顧客企業・担当（FK。付け替えは詳細フォーム）/
自社収益（合成）/ 現在ステップ（フロー列）。

### 追記（2026-08-08、同日）: 実機で欠陥1件 → 決定R で修正

ユーザーの実操作で「フォーカスしてあるセルで Enter を押しても何も起こらない」が発生。
Playwright で再現できた（セルをクリック → **グリッドの外を1回クリック** → 枠は残るが
DOM フォーカスは body → Enter がどこにも届かない）。原因と修正は決定R。修正後に再確認:

- 外をクリックすると枠が消える（嘘の状態が存在しなくなった）
- セルをクリックし直す → Enter でエディタが開く
- フォーカスが無い状態から矢印 / Enter で先頭行に枠が立ち、そのまま編集に入れる
- `pnpm verify` 341 テストのまま通過

**この欠陥は当初の完了条件1の検証をすり抜けた。** 検証が「クリック → 即 Enter」の
1経路だけで、フォーカスが一度グリッドを離れる経路を含んでいなかったため。
グリッドのキーボード配線（keydown → startEdit → エディタ、フォーカスの正直さ）は
当時**ユニットテストが無かった**（純関数 `gridCursor` / `cellEdit` にはあるが、この欠陥は
純関数の層では原理的に捕まらない — DOM フォーカスの所在という**ブラウザ実物の挙動**が
本体のため）。

### 追記2（2026-08-08、同日）: vitest browser mode を導入し、回帰テストを常設した

上の分析を受けて **vitest browser mode（実 Chromium でのコンポーネントテスト）を導入**。
`apps/main` のテストが unit（node・純関数）と browser（`*.browser.test.tsx`）の2層になり、
`pnpm verify` で両方走る。構成は README「ブラウザテスト」と `apps/main/vite.config.ts`。

- ブラウザは **apt の Chromium をイメージに焼き `executablePath` で指す**（Dockerfile）。
  playwright にダウンロードさせない — playwright パッケージの版とブラウザ実体の版が
  結合するのを避ける。pnpm 11 の `allowBuilds` には `playwright: false` を明示
  （postinstall = ブラウザDL を意図的に使わない、の記録）
- `userEvent` は CDP の**実イベント**（isTrusted）で、API は `Client` 注入のスタブ。
  サーバー無しで密閉して回る（1ファイル5テストで +1秒程度）
- テストは5本: **決定Rの再現手順そのもの**（外クリック → 枠が消える → 戻って Enter）/
  キーボードだけの進入 / IME ガード（合成 isComposing・229 では確定せず**実 Enter では
  確定する**対照つき）/ 確定 = PATCH 1回 + 行のその場置換 + フォーカス下移動 /
  書けない行に入れない
- **テスト自体の検証**: 決定Rの修正（`onGridBlur`）を一時的に外して回し、
  該当の1本だけが落ちることを確認した（両方向で通るテストは回帰テストではないため）
- IME の変換確定だけは OS の IME を機械から駆動できない。合成イベント + 対照実験を
  常設回帰とし、実 IME は手動確認に残る（§7 条件3の注のまま）

### 追記3（2026-08-08、同日）: 2件目の「編集できない」は設計どおりの拒否 → 決定S

決定R・回帰テスト常設の後も「Enter で編集モードに入れない」（ユーザーは同一マシンの
**Firefox**）。調査の帰結:

- ユーザーの Firefox（snap プロファイル）の localStorage は **`alt.devUser =
  sato@example.com`（佐藤）** だった。未フィルタ一覧の既定は更新順で、先頭には
  検証中に山田として編集した案件が並ぶ → **先頭画面のほぼ全行が佐藤には編集不可**
  （rowFilter）。リロードしても変わらないのは設計どおりの動作だから
- コンテナに apt の firefox-esr（140）を入れ、puppeteer-core（WebDriver BiDi）で
  素の Firefox を駆動して**ユーザーの状況を完全再現**（佐藤・未フィルタ・先頭行 =
  `focused ro`・Enter / ダブルクリックとも無反応）。山田では Firefox でも編集に
  入れることも確認 — エンジン差ではない。ユーザー環境の拡張機能はゼロ（プロファイルの
  extensions.json で確認）
- **設計どおりの拒否が2回続けて不具合として報告された**のが実際の欠陥 → 決定S
  （理由の表示）。Firefox 再現でメッセージが出ることまで確認し、browser テストに
  2本追加（理由が出る / 編集を始めると消える。計6本）
- 教訓: グリッドの「何も起きない」には設計どおりの3種（決定O）が含まれる。無反応の
  UI は必ず**理由を言葉にする**（サーバの hint を画面に出す方針の FE 版）。
  Firefox の再現は `.ffprobe.tmp`（使い捨て、削除済み）の手順 — apt firefox-esr +
  puppeteer-core で素の Firefox を BiDi 駆動 — でいつでも組み直せる

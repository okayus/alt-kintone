フェーズ $ARGUMENTS の完了処理を行う。**宣言ではなく検証で確かめること。**

1. **完了条件の検証**: `docs/impl/phase-*.md`（フェーズ $ARGUMENTS のファイル）の完了条件を1つずつ、実際にコマンドを実行して確認する。`docker compose exec dev pnpm verify` が通ることも含む。満たせていない条件が1つでもあれば、完了処理を中断してユーザーに報告する
2. **判断の記録漏れ確認**: このフェーズで下した設計判断・実装して見つかった仕様の穴を洗い出し、`docs/product-concept.md` §8-2 と関係する仕様 doc への追記漏れがないか確認する
3. **現在地の更新**: `docs/implementation.md` の現在地表を更新し（完了フェーズ→済、次フェーズ→いまここ）、「すでに動いているもの」を実態に合わせる
4. **CLAUDE.md の更新**: 状況サマリ（最終更新日を含む）と次のアクションを更新する
5. **コミット**: `git status` でユーザーの無関係な未コミット変更が混ざらないか確認したうえで、フェーズの成果をコミットする（メッセージは日本語）
6. 続けて次フェーズに入る場合は `/phase-start` を使う
